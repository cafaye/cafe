=== VERDICT ===

FINDING: caf holds no rows, and the cross-tenant harness is UNDEFINED
  against it — not unfinished. There is no query layer here for it to
  measure.

  caf is a CLI and a gate. It declares no HTTP surface and publishes no
  events (`cafaye.yml`, in its own words). Its four direct dependencies
  are a YAML parser, the MCP SDK, a JSON Schema validator and a URI
  template matcher, and NOT ONE of them is a database driver. It imports
  no database package, ships no .sql and no migrations/ directory, and has
  no tenancy.yml.

  It names `account_id` fourteen times and not one of the fourteen is a
  predicate: every one is the NAME of an OpenTelemetry attribute. That is
  the opposite of a query layer. It is the signature of a service that
  emits telemetry about accounts it forwards to, and forwards the
  authorisation to the service that holds the rows.

  So the packet's premise — `caf | Go | holds rows | yes` — is not
  supported by the tree, and this is reported rather than worked around.
  Manufacturing a subject here would have meant writing a schema for the
  harness to seed, and a green line resting on DDL this repository wrote.
